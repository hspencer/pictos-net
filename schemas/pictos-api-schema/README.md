# PICTOS machine API contracts · 1.1.0

JSON Schemas for the PICTOS machine API v1: one endpoint per pipeline phase, for
server-to-server callers such as Vera. Each endpoint performs a single
transformation, validates its output against a versioned schema and declares
who produced it.

The PICTOS pipeline has four phases: UNDERSTAND (utterance to NLU), COMPOSE
(NLU to visual composition), PRODUCE (composition to image) and the optional
STRUCTURE (image to semantic SVG). Endpoint paths and schema file names keep the
identifiers fixed when version 1.0.0 was published (`comprender`, `componer`,
`producir`, `estructurar`); they are names, not translations, and do not change
within a version.

## Canonical source

Canonical development lives inside `hspencer/pictos-net`, at
`schemas/pictos-api-schema`, next to the endpoints that implement these contracts. This
repository is a one-way export of that directory; changes are proposed there.
The endpoint reference is `docs/API_V1.md` in that repository.

## Contracts

| Schema | Status | Role |
|---|---|---|
| `pictos-api-common-1.0.0` | stable | Shared envelope: success metadata, evidence, quota, errors |
| `pictos-api-comprender-request-1.1.0` / `-response-1.0.0` | stable | UNDERSTAND, served at `POST /api/v1/comprender`: utterance to NLU |
| `pictos-api-componer-request-1.1.0` / `-response-1.0.0` | stable | COMPOSE, served at `POST /api/v1/componer`: NLU to accepted composition |
| `pictos-api-comprender-request-1.0.0`, `pictos-api-componer-request-1.0.0` | frozen | Superseded by 1.1.0; kept at their `$id` |
| `pictos-api-producir-0.1.0-draft` | draft, no endpoint | Future PRODUCE boundary (bitmap or SVG) |
| `pictos-api-estructurar-0.1.0-draft` | draft, no endpoint | Future STRUCTURE boundary |

The phase artifacts are the PICTOS native contracts, published separately:
`pictonet-nlu-generation-1.1.0` (`mediafranca/pictos-nlu-schema`) and
`pictogram-composition-0.1.0` (`mediafranca/pictos-composition-schema`).

Every schema is served at the URL of its `$id`, under
`https://pictos.net/schemas/pictos-api/`. The `examples/` directory holds request
and response documents generated by running the real handlers.

## Versions

1.1.0 (2026-11-08) changes only the `model` field of both request schemas. In
1.0.0 it was an enum of the models offered when it was published; all of them
have since been retired, so a caller could only omit the field. In 1.1.0 it is a
model id, and the server admits it against its model catalog: a retired or
unknown id is rejected with `invalid_request` at `/model`. Every request valid
under 1.0.0 is still valid under 1.1.0, and the endpoints validate against
1.1.0. Model availability is operational, not contractual, and is no longer
written into the schema.

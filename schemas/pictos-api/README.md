# PICTOS machine API contracts · 1.0.0

JSON Schemas for the PICTOS machine API v1: one endpoint per pipeline phase, for
server-to-server callers such as Vera. Each endpoint performs a single
transformation, validates its output against a versioned schema and declares
who produced it.

## Canonical source

Canonical development lives inside `hspencer/pictos-net`, at
`schemas/pictos-api`, next to the endpoints that implement these contracts. This
repository is a one-way export of that directory; changes are proposed there.
The endpoint reference is `docs/API_V1.md` in that repository.

## Contracts

| Schema | Status | Role |
|---|---|---|
| `pictos-api-common-1.0.0` | stable | Shared envelope: success metadata, evidence, quota, errors |
| `pictos-api-comprender-request-1.0.0` / `-response-1.0.0` | stable | `POST /api/v1/comprender`: utterance to NLU |
| `pictos-api-componer-request-1.0.0` / `-response-1.0.0` | stable | `POST /api/v1/componer`: NLU to accepted composition |
| `pictos-api-producir-0.1.0-draft` | draft, no endpoint | Future `producir` boundary (bitmap or SVG) |
| `pictos-api-estructurar-0.1.0-draft` | draft, no endpoint | Future `estructurar` boundary |

The phase artifacts are the PICTOS native contracts, published separately:
`pictonet-nlu-generation-1.1.0` (`mediafranca/nlu-schema`) and
`pictogram-composition-0.1.0` (`mediafranca/pictogram-composition-schema`).

Every schema is served at the URL of its `$id`, under
`https://pictos.net/schemas/pictos-api/`. The `examples/` directory holds request
and response documents generated by running the real handlers.
